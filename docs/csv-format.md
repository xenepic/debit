# CSV 仕様（取り込み側向け）

この拡張機能が出力する CSV の仕様です。Spendly などの取り込み側は、この文書だけで解析と分類ができるようにしています。
例の値はすべて架空です。

## ファイル

| 項目 | 内容 |
|---|---|
| ファイル名 | `aeon-debit_YYYYMM-YYYYMM.csv`（1か月分なら `aeon-debit_YYYYMM.csv`）。範囲は取得した「ご利用分」の最初と最後 |
| 文字コード | UTF-8、BOM 付き |
| 改行 | CRLF（最終行の後にも改行あり） |
| 区切り・引用 | RFC 4180。`,` `"` 改行を含む値、**先頭か末尾に空白がある値**は `"` で囲む（`"` は `""` にエスケープ） |
| ヘッダー | 1行目に必ずある。列順は下表のとおりだが、取り込み側は列名で参照することを推奨 |
| 並び順 | 利用日の昇順、同じ日の中は取引番号の昇順 |
| 重複 | 同じ取引番号は1ファイルに1行だけ |

## サンプル

```csv
取引番号,利用日,利用先,金額,金額区分,確定区分,有効性確認区分,ご利用分
202609010000001,2026/09/01,イオン見本店,1500," ",1,0,2026-09
202609100000002,2026/09/10,イオン見本店,2500," ",1,0,2026-09
202609150000003,2026/09/15,"ｻﾝﾌﾟﾙｼﾖﾂﾌﾟ          ",880," ",1,0,2026-09
202609200000004,2026/09/20,"ﾓﾊﾞｲﾙｻﾝﾌﾟﾙ ﾁﾔ-ｼﾞ    ",3000," ",1,0,2026-09
202609290000005,2026/09/28,EXAMPLE *SUBSCRIPTION,1200," ",1,0,2026-09
```

## 列

値はイオンの明細 API（`GetDebitUseDetail`）の応答を**加工せずに**出力しています。加工しているのは日付の書式だけです。

| 列名 | API の項目 | 形式 | 意味・注意 |
|---|---|---|---|
| 取引番号 | `tradingNumber` | 数字のみ（実例は15桁） | **取引ごとに一意。重複判定のキーに使う。** 先頭8桁は処理日（`YYYYMMDD`）で、利用日より後になることがある（例: 利用日 9/21、取引番号 20260922…） |
| 利用日 | `useDate` | `YYYY/MM/DD` | 利用した日。**時刻はない** |
| 利用先 | `useTarget` | 文字列 | 加盟店名。画面の「利用先」と同じ。表記は次の3種類が混在する（下の「利用先の表記」を参照） |
| 金額 | `price` | 数字のみ（`^\d+$`） | 円。カンマなし、**常に正の数** |
| 金額区分 | `priceCode` | 1文字 | 確認できた値は半角空白 `" "` だけ。返品・取消などで `-` 等になる可能性があるが未確認 |
| 確定区分 | `fixedState` | 1文字 | `1` = 確定（画面の「ご利用状態: 確定」）。それ以外の値は未確認（未確定と推測） |
| 有効性確認区分 | `effectivenessConfirmationTransactionKubun` | 1文字 | 確認できた値は `0` だけ。`0` 以外はカードの有効性確認（実際の支払いではない）と推測 |
| ご利用分 | `referenceYearMonth` | `YYYY-MM` | どの月の明細ページから取得したか。通常は利用日の年月と同じ |

### 利用先の表記

| 種類 | 例 | 特徴 |
|---|---|---|
| 全角 | `イオン見本店` | イオングループの店舗に多い。空白埋めなし |
| 半角カナ | `ｻﾝﾌﾟﾙｼﾖﾂﾌﾟ          ` | 外部の加盟店。**20文字に満たない分を末尾に半角空白で埋めてある**。長音は `-`、小書き文字（ャュョッ）は大きい文字（ﾔﾕﾖﾂ）で表記される |
| 英数字 | `EXAMPLE *SUBSCRIPTION` | 海外・オンラインサービス。20文字で切れていることがある |

取り込み時は `normalize('NFKC')` と `trim()` を推奨します。たとえば `ﾓﾊﾞｲﾙｻﾝﾌﾟﾙ ﾁﾔ-ｼﾞ` は `モバイルサンプル チヤ-ジ` になります（「チャージ」にはならない点に注意）。

## 取り込み側での推奨ルール

| 条件 | 扱い |
|---|---|
| `確定区分` が `1` 以外 | 取り込まない（未確定の利用は後で確定し、金額が変わることがある） |
| `有効性確認区分` が `0` 以外 | 取り込まない（支払いではない） |
| `金額区分` が空白以外 | 「要確認」にして手動で判断する（返品などの可能性） |
| 利用先が NFKC 後に `/チ[ヤャ][-ー]ジ/` を含む | **チャージ**（電子マネー・交通系IC・PayPay 等への入金）。支出には含めない。PayPay へのチャージを支出に数えると、PayPay 側の支払いと二重計上になる |
| 上記以外 | 支払い（支出） |

その他:
- 日時は `利用日` + `T00:00` とする。方向はすべて出金
- 同じ取引番号は、ファイルが変わっても同じ取引を指す。複数のファイルで期間が重なっても、取引番号で重複を除外すれば二重に取り込まれない
- 1か月分の明細はすべて1回の API 応答で取得している（画面の10件表示の制限は受けない）。そのため、ある「ご利用分」がファイルに含まれていれば、その月の明細は全件そろっている
- サイトでさかのぼれるのは約半年分

## 判別方法

1行目（BOM を除く）が次のヘッダーと一致すれば、この形式です。

```
取引番号,利用日,利用先,金額,金額区分,確定区分,有効性確認区分,ご利用分
```

列を追加する場合は末尾に追加し、既存の列名と意味は変更しません。
